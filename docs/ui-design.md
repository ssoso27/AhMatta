# AhMatta 화면 기준

2026-09-18 · 제품 흐름은 사용자 검토 완료. 아래 시각 값은 첫 화면을 위한 기본안이며 사용자 시각 검증 전이다.

## 이 화면이 해야 하는 일

앱을 잠깐 봤을 때 지금 하는 일, 하다 만 일, 누를 버튼을 구분할 수 있어야 한다. 사용자는 읽기에 어려움이 있다고 알려주었으며, 디자인 요구를 상세히 설명하기 어렵고 답이 늦을 수 있다. 이를 개인의 실제 선호로 다룬다. 특정 장애에 항상 맞는 서체·색·크기가 있다고 가정하지 않는다.

빠른 파악의 목표는 첫 화면에서 약 3초 안에 현재 작업을 찾고, 돌아갈 작업의 위치를 아는 것이다. 이는 제품 목표이며 아직 측정된 결과나 접근성 인증이 아니다.

## 유지할 뼈대

- 지금 화면: 현재 작업 → 하다 만 작업 → 답할 요청 → 할 일.
- 현재 작업이 없으면 같은 위치에 '지금 하는 일 없음'과 시작할 수 있는 행동을 표시한다.
- 시작·재개 버튼은 같은 위치와 표현 체계를 쓴다. 현재 작업의 완료 버튼은 시작·재개와 혼동되지 않게 구분한다.
- 하단 메뉴: 지금 / 기록 / 설정. 간트는 기록 화면에 둔다.
- 작업 전환 한 번으로 이전 구간 종료와 새 구간 시작. 메모는 선택.
- 답장과 완료는 다른 상태이며, 중단 작업을 접거나 필터링할 때도 개수와 펼칠 방법이 보인다.
- 사용자가 읽거나 클릭하려는 동안 항목을 갑자기 재정렬하지 않는다. 새 요청은 도착 표시 후 목록에 반영하며 현재 작업 위치는 고정한다.

이 뼈대는 변경 금지가 아니다. '메뉴를 위로 옮겨' 같은 명시적 요청이나 실제 사용에서 드러난 구조 문제를 근거로 바꾼다. '답답해'만으로 메뉴·정렬·색을 동시에 바꾸지 않는다.

## 조정 가능한 기본값

| 요소 | 첫 기본안 | 확인할 점 |
|---|---|---|
| 창 | 400×760 px, 360 px 폭도 확인 | 핵심 버튼이 밖으로 밀리지 않는가 |
| 본문 / 작업명 | 시스템 한글 고딕, 16 / 18 px | 큰 글자가 필요한지 실제 피드백으로 조정 |
| 보조 글자 | 14 px | 작업 구분에 꼭 필요한 정보는 작게 낮추지 않음 |
| 행간 | 1.5 | 한글 줄바꿈·제목 두 줄에서도 읽을 수 있음 |
| 정렬 | 왼쪽 정렬 | 양쪽 맞춤과 긴 중앙 정렬 문단 없음 |
| 간격 | 4·8·12·16·24 px 단계 | 작업 카드 내부와 카드 사이가 구분됨 |
| 핵심 버튼 | 높이 44 px 이상을 목표 | 버튼 간 오클릭, 키보드 포커스 확인 |
| 표면 | 밝은 중립 배경, 구분되는 카드 | 장식보다 현재 작업과 행동이 먼저 보임 |
| 강조 | 현재 작업에 가장 강한 강조 | 모든 카드가 같은 강도로 튀지 않음 |
| 작업 색 | 카드 전체 대신 작은 표시와 간트 막대 | 색을 몰라도 제목·상태로 구분 가능 |

크기와 색은 토큰으로 모아 조정한다. 여백을 늘려 중단 작업을 화면 아래로 밀어내거나 글자를 줄여 정보량을 맞추지 않는다. 먼저 부가 정보를 접는다. 긴 작업명은 목록에서 두 줄까지 보여주되 전체 제목을 키보드와 클릭으로 확인할 수 있게 한다.

상태 용어는 화면 전반에서 통일한다. '하다 만 작업' 같은 사용자 말에 가까운 제목과 '시작', '이어 하기', '완료', '원문 열기' 같은 동사를 사용한다. 핵심 행동을 아이콘만으로 표시하지 않는다. 초 단위로 커지는 타이머나 장식 애니메이션보다 작업명이 먼저 보이게 한다.

## 첫 시안의 범위

실제 비교 가능한 주안 하나로 시작한다. 구조의 선택이 정말 필요할 때만 같은 데이터로 차이가 한 가지인 대안 하나를 추가한다. 사용자가 답하지 않아도 기본안으로 초안을 구체화하되, 침묵을 승인이나 선호 확정으로 기록하지 않는다.

예시 데이터는 짧은 영어 제목 대신 다음 상황을 담는다.
- 현재: '카미오시 투표 집계 오류 확인', 요청자, 23분 경과.
- 중단: '셀럽 배너 노출 조건 수정', '최애돌 로그인 문의 확인'.
- 긴 이름과 두 줄을 넘는 작업명, 어제부터 남은 작업, 링크 없는 수동 작업.
- 요청 0개와 20개, 현재 작업 없음, 서버 연결 끊김.

첫 화면은 정보 배치와 행동을 확인하고, 이후 글자·여백을 다듬고, 마지막에 색과 장식을 조정한다. 문서만으로 시각 설계가 검증됐다고 하지 않는다.

## 짧은 피드백을 처리하는 방법

1. 현재 화면·기존 기준과 사용자의 표현을 확인한다. 실제 화면이 없으면 가설로 표시한다.
2. 관찰 / 원인 가설 / 이번에 바꿀 축을 짧게 정한다.
3. 정보량, 강조, 글자, 여백, 색, 행동 발견 중 가장 관련된 축 1개, 필요하면 2개를 수정한다. 여러 축이 불가분이면 이유를 기록한다.
4. 같은 작업 데이터와 같은 창 크기로 전후를 비교한다. 구현이 있으면 실제 렌더링과 동작을 확인한다.
5. 사용자에게는 바뀐 점 1~2개와 화면을 보여준다. 질문이 꼭 필요하면 '글자가 작은 쪽 / 내용이 많은 쪽'처럼 짧은 선택 하나만 묻는다.
6. 수정과 결과를 아래 기록에 남긴다. 사용자 확인이 없으면 '가설·검증 전' 상태를 유지한다.

| 사용자 표현 | 우선 살펴볼 가설 | 첫 수정 후보 |
|---|---|---|
| 뭐 해야 하는지 안 보여 | 현재 작업과 주 행동의 강조가 약함 | 현재 작업 제목·시작/재개 버튼 강조 |
| 답답해 | 첫 화면 정보가 많거나 카드 크기가 과함 | 부가 정보 접기 또는 카드 안 여백 조정 |
| 정신없어 | 색·테두리·배지·움직임이 경쟁함 | 보조 강조를 한 단계 낮춤 |
| 읽기 힘들어 | 크기·대비·줄바꿈·행간 중 문제 | 화면을 보고 관련 값부터 조정 |
| 색이 싫어 | 선호하는 색감과 다름 | 배치를 유지한 채 색 토큰 수정 |
| 다 별로야 | 구체적 원인이 아직 없음 | 기존 화면에서 가장 강한 문제 하나를 가설로 잡고 작은 수정안 제시 |

이 표는 진단표가 아니다. 실제 화면과 다음 피드백이 가설보다 우선한다.

## 완료 전 확인

- 현재 작업, 중단 작업의 위치, 주요 행동을 설명 없이 찾을 수 있는가? 에이전트 검토와 실제 사용자 결과를 구분한다.
- 400×760, 폭 360, 200% 확대에서 핵심 작업 흐름을 사용할 수 있는가? 확대 시 세로 스크롤은 허용한다.
- 작업 목록 전체에 가로 스크롤이 생기지 않는가? 간트 시간축은 예외다.
- 본문 대비 4.5:1 이상, 큰 글자 3:1 이상을 확인한다. 단순 색상값 선언만으로 통과를 주장하지 않는다.
- 텍스트 간격을 사용자가 변경해도 내용과 행동이 잘리지 않는가? WCAG 텍스트 간격 기준은 지원하는 언어 속성에 적용하며, 그 수치를 한글 기본 자간으로 강제하지 않는다.
- 키보드로 등록·시작·재개·완료·원문 열기를 수행할 수 있고 포커스가 보이는가?
- 색을 제거해도 상태를 구분할 수 있는가?
- A→B→C 후 A·B가 남고, 답장을 했다는 이유로 완료되지 않는가?

검증하지 못한 항목은 미검증으로 표시한다. 사용자의 읽기 경험은 에이전트가 대신 인증할 수 없다.

- 사용자 확인: 제품 흐름은 '대강 봤어. 괜찮네.'로 수용.
- 사용자 요구: 빠르게 보고 파악, 직관적인 UI, 상세한 디자인 설명 부담 줄이기, 처음 틀을 잡고 조금씩 수정.
- 적용: 유지할 뼈대와 조정 가능한 기본값을 구분. 짧은 피드백을 가설과 작은 수정으로 연결.
- 아직 미확인: 글자 크기, 색상, 여백, 실제 화면의 빠른 파악 정도.

후속 기록에는 날짜 / 피드백 원문 / 관찰과 가설 / 변경한 축 / 확인 결과 / 유지하거나 되돌릴 내용을 남긴다. 한 번의 의견을 영구 선호로 확정하지 않는다.
